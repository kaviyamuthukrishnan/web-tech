GET vs POST Form Methods

Web Technology Lab Exercise

1. Form Using GET Method

Data submitted here is appended to the URL as a query string, so it's visible in the address bar and can be bookmarked or shared.

Observe: After submitting, check the browser's address bar — you'll see something like ?studentName=...&course=... appended to the URL. This is why GET is not suitable for sensitive data like passwords.

2. Form Using POST Method

Data submitted here is sent in the HTTP request body, so it does NOT appear in the URL — better suited for sensitive or large data.

Observe: After submitting, the URL stays as https://httpbin.org/post — no form data is visible in the address bar. The submitted values instead appear inside the JSON response body under the "form" key.

Key Differences: GET vs POST

Aspect GET POST
Data Visibility Visible in URL (query string) Hidden in request body
Data Length Limit Limited (URL length restrictions) No practical limit
Bookmarking Can be bookmarked (data included) Cannot be bookmarked with data
Security Less secure, data exposed More secure for sensitive data
Use Case Search forms, filters Login forms, registration, file uploads
